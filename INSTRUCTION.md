# Как запустить сайт «Тайный Санта» в интернете — бесплатно, на GitHub Pages

Это единая инструкция. Идите по шагам сверху вниз, ничего не пропуская и не меняя порядок.

**Как это устроено.** У сайта нет своего сервера, поэтому хостинг вообще не нужен:

- **GitHub Pages** — бесплатно показывает сам сайт (адрес вида `ваш-логин.github.io/название/`). Работает из России без VPN.
- **Supabase** — бесплатно хранит базу данных (комнаты, участники, подарки) и вход по почте. Браузер обращается к нему напрямую.

Прямой доступ к таблицам закрыт, а вся логика — жеребьёвка, пары, права организатора — выполняется внутри базы данных специальными функциями. Подсмотреть чужую пару через браузер нельзя: база отдаёт каждому только то, что ему положено.

**Итого: 0 ₽ в месяц, карта нигде не нужна.**

**Начинаем с чистого листа.** Ниже — запуск с нуля: новая папка, новый репозиторий, новый проект Supabase. Старые репозитории и проекты Supabase не трогаем — они не помешают, удалить их можно потом.

**Что мы сделаем:**

| Часть | Что делаем | Шаги |
| --- | --- | --- |
| A | Заводим аккаунты и ставим программу | 1–3 |
| B | Настраиваем Supabase: база данных и вход | 4–8 |
| C | Создаём новый репозиторий и загружаем код через GitHub Desktop | 9–13 |
| D | Включаем GitHub Pages и получаем адрес сайта | 14–17 |
| E | Проверяем, что всё работает, и приглашаем друзей | 18–24 |

Займёт около 40 минут.

**Названия кнопок.** Сайты иногда переименовывают кнопки и пункты меню. Если пункт называется чуть иначе, ищите похожий по смыслу. Названия кнопок выделены **жирным**.

---

## А почему не Google Таблицы?

Коротко: таблицы не умеют то, что нужно сайту. У них нет настоящих прав доступа (кто угодно с ключом прочитал бы секретные пары), нет транзакций (два человека нажмут «жеребьёвку» одновременно — пары перемешаются и сломаются), есть жёсткие квоты на запросы, а сайт опрашивает данные каждые 4 секунды. Supabase — это тоже бесплатно, но это настоящая база данных. Поэтому таблицы не используем.

## Блокнот для записей

По ходу работы вам нужно будет сохранить всего 2 значения. Откройте обычный текстовый файл и заранее скопируйте в него эту таблицу. Каждое значение вы запишете в нужный момент, а на шаге 14 перенесёте в Secrets репозитория.

| Что записать | Где получите | Заполнить |
| --- | --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | Шаг 7 | |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Шаг 7 | |

Секретный ключ и пароль от базы сайту **не нужны** — только эти два публичных значения.

# Часть A. Подготовка

## Шаг 1. Аккаунт GitHub

1. Откройте [github.com](https://github.com).
2. Нажмите **Sign up** и пройдите регистрацию: почта, пароль, имя пользователя.
3. Подтвердите почту по письму от GitHub.

Если аккаунт у вас уже есть, просто войдите в него.

## Шаг 2. GitHub Desktop

1. Откройте [desktop.github.com](https://desktop.github.com) и скачайте программу для вашей системы (Windows или macOS).
2. Установите её как обычную программу и запустите.
3. Нажмите **Sign in to GitHub.com**. Откроется браузер: нажмите **Authorize desktop** и вернитесь в программу.
4. На экране **Configure Git** оставьте имя и почту как есть и нажмите **Finish**.

## Шаг 3. Аккаунт Supabase

1. Откройте [supabase.com](https://supabase.com) и нажмите **Start your project**.
2. Выберите **Continue with GitHub** и разрешите доступ. Так проще всего: отдельный пароль не нужен.

Supabase открывается из России без VPN. Платный тариф не нужен — сайт работает на бесплатном.

# Часть B. Supabase

## Шаг 4. Создайте проект

1. Войдите на [supabase.com/dashboard](https://supabase.com/dashboard).
2. Нажмите **New project**. Если просят создать организацию, согласитесь: название любое, тип **Personal**, тариф **Free**.
3. Заполните поля:
   - **Project name**: например, `secret-santa`.
   - **Database Password**: нажмите **Generate a password**. Этот пароль сайту не нужен (прямого подключения к базе больше нет), но Supabase просит его придумать. Сохраните его куда-нибудь на всякий случай.
   - **Region**: выберите ближайший к вам, например **Central EU (Frankfurt)**.
4. Нажмите **Create new project** и подождите 1–2 минуты, пока проект создаётся.

## Шаг 5. Создайте таблицы и логику сайта

1. В левом меню проекта нажмите **SQL Editor**.
2. Нажмите **New query** (или **+**), чтобы открыть пустой запрос.
3. На своём компьютере откройте в папке проекта файл `supabase/schema.sql` любым текстовым редактором, например Блокнотом.
4. Выделите весь текст (**Ctrl+A**, на Mac **Cmd+A**), скопируйте (**Ctrl+C**) и вставьте в окно запроса в Supabase (**Ctrl+V**).
5. Нажмите зелёную кнопку **Run** (или **Ctrl+Enter**).
6. Внизу должно появиться сообщение **Success. No rows returned**. Это значит, что всё получилось.
7. Проверьте результат: в левом меню нажмите **Table Editor**. В списке слева должны быть четыре таблицы: `assignments`, `participants`, `profiles`, `rooms`.

Если появилась красная ошибка, скопируйте её текст и покажите мне. Файл можно запускать повторно: уже созданные таблицы и данные он не трогает.

## Шаг 6. Отключите подтверждение почты (важно!)

Сайт регистрирует мгновенно, без писем с подтверждением, поэтому Supabase не должен требовать подтверждения адреса. Без этого шага регистрация не будет работать.

1. В левом меню нажмите **Authentication**, затем **Sign In / Up** (или **Providers** — зависит от версии панели).
2. Найдите провайдер **Email** и откройте его настройки.
3. Выключите переключатель **Confirm email** (в некоторых версиях он называется **Confirm email addresses**). Должно стать **Off**.
4. Сохраните (**Save**), если есть такая кнопка.

## Шаг 7. Скопируйте адрес проекта и публичный ключ

1. Нажмите на шестерёнку **Project Settings** в левом меню внизу.
2. Адрес проекта: раздел **Data API** (или кнопка **Connect** вверху страницы) → **Project URL**, адрес вида `https://abcdefghijk.supabase.co`. Запишите в блокнот напротив `NEXT_PUBLIC_SUPABASE_URL`.
3. Ключ: раздел **API Keys**.
   - На новых проектах нужен **Publishable key**, начинается с `sb_publishable_`. Запишите напротив `NEXT_PUBLIC_SUPABASE_ANON_KEY`.
   - В старых проектах откройте вкладку **Legacy API Keys** и скопируйте ключ **anon public**.
4. **Секретный ключ (Secret / service_role) НЕ копируйте** — он больше не используется. Никому его не показывайте.

## Шаг 8. Проверьте блокнот

Обе строки в таблице должны быть заполнены. Проверьте:

- `NEXT_PUBLIC_SUPABASE_URL` начинается с `https://` и заканчивается на `.supabase.co`;
- ключ скопирован целиком, без пробелов в начале и конце.

# Часть C. Новый репозиторий и загрузка кода

## Шаг 9. Создайте новую пустую папку и скопируйте в неё файлы сайта

Берём файлы из вашей текущей папки проекта, но в новую папку — без старого мусора. Это важно: вместе со старыми служебными файлами переезжают и старые ошибки.

1. Создайте на компьютере новую пустую папку, например `santa-site`.
2. Откройте старую папку проекта и скопируйте из неё в новую папку **только это**:
   - папки: `src`, `supabase`, `.github`
   - файлы: `package.json`, `package-lock.json`, `tsconfig.json`, `next.config.ts`, `postcss.config.mjs`, `eslint.config.mjs`, `.gitignore`, `.gitattributes`, `.env.example`, `INSTRUCTION.md`, `README.md`
3. **Не копируйте**: папку `.git`, файл `.env`, папки `node_modules`, `.next`, `out`.

Подсказки:
- На Windows файлы с точкой в начале (`.github`, `.gitignore`, `.env.example`) обычно видны сразу.
- На Mac такие файлы скрыты: нажмите **Cmd+Shift+.** (точка), чтобы их увидеть, скопируйте, затем нажмите ещё раз, чтобы скрыть обратно.
- Папка `.git` — самая важная: её копировать **нельзя**. Иначе GitHub Desktop решит, что это старый репозиторий, и всё запутается.
- `package-lock.json` скопировать **обязательно** — без него сборка упадёт с ошибкой «Dependencies lock file is not found».

## Шаг 10. Добавьте новую папку в GitHub Desktop

1. Откройте GitHub Desktop.
2. В меню выберите **File → Add local repository...**.
3. Нажмите **Choose...** и выберите **новую** папку. Нажмите **Add repository**.
4. Появится предупреждение «This directory does not appear to be a Git repository» — так и должно быть, папка же новая. Нажмите ссылку **create a repository**. В открывшемся окне ничего не меняйте и нажмите **Create repository**.

Если предупреждения не было, а открылся старый репозиторий со старой историей — значит, вы выбрали не ту папку (или скопировали `.git`). Начните шаг 9 заново.

## Шаг 11. Проверьте список файлов и сохраните версию

1. На вкладке **Changes** слева виден список файлов, которые уйдут на GitHub.
2. Убедитесь, что в нём **нет** файла `.env` и папки `node_modules`. Их скрывает файл `.gitignore`.
3. Убедитесь, что в нём **есть** файлы `package-lock.json`, `package.json`, `.env.example` и папки `src`, `supabase`, `.github`.

Если файла `.env` всё же есть в списке, остановитесь: проверьте, что файл `.gitignore` скопировался в новую папку (он скрытый — см. подсказки в шаге 9).

4. Внизу слева, в поле **Summary**, напишите `Первая версия`.
5. Нажмите синюю кнопку **Commit to main** (кнопка может называться **Commit to master** — тоже нормально).

## Шаг 12. Опубликуйте репозиторий

1. Нажмите **Publish repository** вверху окна.
2. Укажите имя, например `secret-santa`. Имя может быть любым.
3. Галочка **Keep this code private** делает репозиторий закрытым. Закрытый выбирайте, если не хотите показывать код другим. GitHub Pages работает в обоих случаях.
4. Нажмите **Publish repository**.

Важно: не создавайте репозиторий заранее на сайте github.com — пусть его создаст GitHub Desktop этой кнопкой. Иначе имена разойдутся и начнутся ошибки.

## Шаг 13. Проверьте результат на GitHub

1. Откройте [github.com](https://github.com) и перейдите в свой новый репозиторий.
2. Убедитесь, что там видны: папки `src`, `supabase`, `.github`, файлы `package.json`, `package-lock.json`, `INSTRUCTION.md`, `README.md`, `.gitignore`, `.env.example`, `next.config.ts`, `tsconfig.json`.
3. Убедитесь, что файла `.env` там **нет**.

Если чего-то не хватает — вернитесь к шагу 9 и докопируйте файлы, затем повторите шаги 11–12 (кнопка будет называться **Push origin**).

# Часть D. Публикация сайта на GitHub Pages (бесплатно)

## Шаг 14. Добавьте два секрета в репозиторий

Секреты — это значения из блокнота. Они нужны только во время сборки сайта и никому не видны.

1. На странице репозитория нажмите **Settings** (вкладка вверху).
2. Слева выберите **Secrets and variables** → **Actions**.
3. Нажмите **New repository secret** и добавьте первый секрет:
   - **Name**: `NEXT_PUBLIC_SUPABASE_URL`
   - **Secret**: адрес проекта из блокнота.
   - Нажмите **Add secret**.
4. Ещё раз **New repository secret** и добавьте второй:
   - **Name**: `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - **Secret**: публичный ключ из блокнота.
   - Нажмите **Add secret**.
5. Проверьте: в списке должно быть два секрета с точными именами (регистр важен, без пробелов).

## Шаг 15. Включите GitHub Pages

1. На странице репозитория нажмите **Settings**.
2. Слева выберите **Pages**.
3. В разделе **Build and deployment**, в пункте **Source**, выберите **GitHub Actions** (а не Deploy from a branch).
4. Больше ничего менять не нужно — страницу можно закрыть.

## Шаг 16. Запустите сборку и получите адрес сайта

1. Откройте вкладку **Actions** в репозитории.
2. Слева выберите **Deploy to GitHub Pages**.
3. Нажмите **Run workflow** → **Run workflow** справа. (Первая автоматическая сборка после публикации могла упасть — это нормально: тогда ещё не было секретов. Сейчас всё настроено.)
4. Подождите 2–4 минуты, пока сборка завершится (все шаги зелёные).
5. Адрес сайта: `https://ВАШ-ЛОГИН.github.io/НАЗВАНИЕ-РЕПОЗИТОРИЯ/`. Точную ссылку показывает и страница **Settings → Pages** вверху.
6. Вернитесь в Supabase: **Authentication → URL Configuration**, в поле **Site URL** впишите адрес сайта из пункта 5 (целиком, со слэшем в конце) и сохраните. Без этого не будут работать письма восстановления пароля.
7. Откройте адрес в браузере. Сайт должен открыться из России без VPN: ёлка с подарками и блок **Регистрация / Вход**.

Если сборка завершилась красным крестиком, откройте её, нажмите на упавший шаг и прочитайте ошибку. Частые случаи — в разделе «Если что-то не работает» в конце инструкции.

**Свой домен (необязательно).** Если хотите адрес вида `santa.вашдомен.ru`: привяжите домен в **Settings → Pages → Custom domain** (GitHub покажет, какую запись создать у регистратора), а затем откройте в репозитории файл `.github/workflows/deploy.yml` (карандашик **Edit**), найдите строку `NEXT_PUBLIC_BASE_PATH: /${{ github.event.repository.name }}` и замените её на `NEXT_PUBLIC_BASE_PATH: ""`, после чего сохраните (**Commit changes**). Сборка запустится заново.

## Шаг 17. Проверьте главную страницу

1. Откройте адрес сайта из шага 16.
2. Вы должны увидеть ёлку с подарками и справа блок **Регистрация / Вход**.
3. Жёлтого предупреждения «сайт не подключён к Supabase» быть не должно. Если оно есть, значит, секреты не подхватились: проверьте шаг 14 (точные имена, значения без пробелов) и перезапустите сборку (вкладка **Actions** → **Re-run jobs**).
4. Блока **Создать комнату** сейчас быть не должно. Он появляется только после входа.

# Часть E. Проверка

## Шаг 18. Зарегистрируйтесь

1. В блоке нажмите вкладку **Регистрация**.
2. Заполните поля:
   - **Электронная почта**: например, `ivan@example.com`;
   - **Пароль**: от 6 символов;
   - **Повторите пароль**: тот же пароль ещё раз;
   - **Имя, которое будет отображаться на сайте**: например, `Иван`.
3. Нажмите **Зарегистрироваться**.
4. Для проверки используйте настоящую почту, к которой у вас есть доступ, — она понадобится для проверки восстановления пароля на шаге 21.
5. Вы сразу войдёте в профиль: в блоке появится «Вы вошли в профиль» и ваше имя. Под ним появится блок **Создать комнату**.

Если вместо входа ошибка про подтверждение почты — вернитесь к шагу 6: переключатель **Confirm email** должен быть выключен.

## Шаг 19. Создайте тестовую комнату

1. В блоке **Создать комнату** впишите название, например `Тест`.
2. Выберите аватар и цвет. Имя по умолчанию берётся из профиля, а позже его, аватар и цвет можно поменять кнопкой **✏️ Редактировать** в карточке участника.
3. Нажмите **Создать комнату**. Откроется страница комнаты с ёлкой. Адрес комнаты выглядит так: `.../room?code=ABC123`.

## Шаг 20. Убедитесь, что данные попали в Supabase

1. Откройте [supabase.com/dashboard](https://supabase.com/dashboard) и зайдите в свой проект.
2. В левом меню нажмите **Table Editor** и откройте таблицу `rooms`: в ней должна быть строка с комнатой `Тест`.
3. Откройте таблицу `profiles`: в ней должен быть ваш профиль с вашей почтой.
4. В левом меню откройте **Authentication → Users**: там появился пользователь с вашей почтой.

## Шаг 21. Проверьте выход, вход и восстановление пароля

1. На главной странице нажмите **Выйти**. Блок **Создать комнату** должен исчезнуть.
2. Откройте вкладку **Вход**, введите почту и пароль и нажмите **Войти**. Блок **Создать комнату** должен появиться снова.
3. Выйдите ещё раз. Нажмите **Забыли пароль?**, введите почту и нажмите **Отправить ссылку**.
4. Откройте письмо и перейдите по ссылке — сайт предложит придумать новый пароль, после чего вы сразу войдёте. Если письма нет, проверьте папку «Спам» и пункт 6 шага 16 (Site URL).

## Шаг 22. Пригласите друзей

1. Откройте свою комнату. Справа вверху нажмите **🔗 Пригласить** — эту кнопку видит только организатор.
2. Откроется окно с QR-кодом, а под ним — код комнаты из 6 символов.
3. Друзья могут попасть в комнату тремя способами:
   - навести камеру телефона на QR-код;
   - открыть ссылку (кнопка **Скопировать ссылку**);
   - ввести код на главной странице в блоке **Войти по коду**.
4. **В комнату пускают только после входа в профиль.** Если друг не вошёл, сайт сам откроет окно «Регистрация / Вход». После регистрации он сразу попадёт в комнату, выберет аватар и цвет и нажмёт **Войти в комнату**.

## Шаг 23. Проверьте жеребьёвку, подарок и его принятие

1. Войдите вторым профилем (или попросите друга), проведите жеребьёвку в панели организатора.
2. Сразу после жеребьёвки у каждого участника вместо карточки «Вы — Тайный Санта для» крутится рулетка из всех участников: она останавливается на том, кому достался подарок. Это показывается один раз для каждой новой жеребьёвки.
3. Санта выбирает упаковку и нажимает **Я отправил подарок** — блок сворачивается в компактную строку со стрелкой, а под ёлкой появляется цветной подарок.
4. У получателя над блоком «Вы — Тайный Санта для» появляется блок **Вам подарок** с кнопкой **Принять**.
5. После нажатия **Принять** крышка коробки съезжает вбок, бантик лежит рядом, из подарка видно то, что положил Санта (у пакета опускаются ручки). Надпись становится «Подарок принят», а кнопка меняется на «Подарок получен». Рамка имени становится зелёной.

## Шаг 24. Проверьте телефон

Откройте сайт с телефона (по ссылке или QR-коду): главная и комната должны выглядеть аккуратно, кнопки нажиматься. Если что-то не влезает в экран — напишите мне, поправлю.

Если все шаги прошли, сайт готов.

## Что умеет организатор

Название комнаты можно поменять: рядом с ним есть кнопка с карандашом ✏️. Блок **Участники** в комнате показывает всех; новых участников приглашайте ссылкой или QR-кодом.

В комнате под блоком **Участники** есть **Панель организатора** с двумя разделами. Нажмите на раздел, чтобы раскрыть его (стрелка справа).

- **🎲 Жеребьёвка**: кнопки **Рандом для всех**, **Рандом для оставшихся**, **Сбросить** и **Показать пары / Скрыть**. Ниже — список, в котором можно назначить Санту вручную.
- **⚙️ Настройка комнаты**: кто видит пожелания на подарке — **Всем участникам** или **Только Санте**.

## Как Санта отмечает подарок

1. В карточке «Вы — Тайный Санта для…» выберите упаковку: **Пакет** или **Подарок**, затем цвет.
2. Нажмите **📦 Я отправил подарок**.
3. Под ёлкой серый подарок со знаком «?» станет пакетом или коробкой выбранного цвета. Упаковку можно поменять и после отправки.

Доступные цвета: красный, оранжевый, жёлтый, зелёный, голубой, синий, фиолетовый, белый и чёрный. Внутрь подарка всегда кладутся конфеты — после принятия получатель увидит их в открытой упаковке.

# После запуска

## Как обновлять сайт

Когда в проекте что-то изменилось, например я внёс правки:

1. Откройте GitHub Desktop: изменённые файлы появятся на вкладке **Changes**.
2. **Посмотрите, есть ли в списке файл `supabase/schema.sql`.** В этой версии добавлены новые цвета и наполнения подарков. Старые цвета (золотой, розовый, бирюзовый) сменятся на ближайшие новые автоматически, данные комнат сохранятся. Если есть, сначала обновите базу: повторите шаг 5 — скопируйте файл целиком в **SQL Editor** и нажмите **Run**. Существующие данные он не трогает, а новые колонки и функции добавляет. Если пропустить этот пункт, после обновления сайт будет выдавать ошибки.
3. Напишите описание в поле **Summary**, например `Правки`, и нажмите **Commit to main**.
4. Нажмите **Push origin** вверху.
5. GitHub сам пересоберёт сайт. Прогресс виден на вкладке **Actions**; обычно это занимает 2–4 минуты. После зелёной галочки обновите страницу сайта (иногда помогает **Ctrl+F5**).

## Как изменить секрет

1. Откройте репозиторий → **Settings** → **Secrets and variables** → **Actions**.
2. Нажмите на карандашик у нужного секрета, впишите новое значение и сохраните.
3. Перезапустите сборку: вкладка **Actions** → последняя сборка → **Re-run jobs**. Без пересборки новое значение не подхватится (ключи вшиваются в сайт при сборке).

## Как «разбудить» Supabase

Бесплатный проект Supabase «засыпает», если к базе неделю никто не обращался. Тогда сайт покажет ошибки при входе. Это лечится за минуту:

1. Откройте [supabase.com/dashboard](https://supabase.com/dashboard).
2. Зайдите в свой проект и нажмите **Restore project** / **Resume**.
3. Подождите пару минут — сайт снова работает.

## Как запустить сайт на своём компьютере (необязательно)

1. Установите [Node.js](https://nodejs.org) (версия LTS, 20 или новее).
2. В папке проекта скопируйте файл `.env.example` и назовите копию `.env`.
3. Откройте `.env` в Блокноте и вместо примеров впишите два значения из блокнота.
4. Откройте терминал в папке проекта и выполните по очереди:

   ```bash
   npm install
   npm run dev
   ```

5. Откройте в браузере `http://localhost:3000`.

# Как устроен вход по почте

При регистрации пользователь указывает настоящую почту, пароль дважды и имя для сайта. Подтверждать почту письмом не нужно: профиль создаётся мгновенно (поэтому важен шаг 6). В **Authentication → Users** вы увидите пользователей с их настоящими адресами.

- Если человек забыл пароль, он нажимает **Забыли пароль?**, вводит почту и переходит по ссылке из письма, после чего придумывает новый пароль и сразу входит. Для этого нужен правильный **Site URL** (пункт 6 шага 16).
- Регистр почты не важен: `Ivan@Example.com` и `ivan@example.com` — один профиль. Пароль — от 6 символов.
- Если человек потерял доступ и к почте, пусть зарегистрируется заново с новой почтой, а в комнаты вступит повторно. Прежнего его участника организатор может удалить из комнат, чтобы не было двойников.

Имя, указанное при регистрации, показывается на сайте и становится именем организатора в созданных комнатах.

# Если что-то не работает

| Что видно | В чём причина | Что сделать |
| --- | --- | --- |
| В GitHub Desktop нет кнопки Publish, видна старая история | Папка скопирована вместе со старым `.git` | Начните часть C заново: новая пустая папка, скопируйте файлы строго по списку из шага 9, без папки `.git` |
| Предупреждение про отсутствующий `package-lock.json` | Файл не выгружен в репозиторий | Сборка всё равно завершится успешно. Но лучше закоммитьте `package-lock.json` и нажмите **Push origin** — запустится новая быстрая сборка |
| Рулетка после жеребьёвки крутится снова | Она показывается один раз для каждой жеребьёвки. Сбросилось, если вы открыли сайт в другом браузере или очистили данные браузера | Это нормально: рулетка просто показывает результат ещё раз. Результат тот же |
| Старый цвет подарка (золотой, розовый, бирюзовый) исчез | Цвета обновлены до нового набора | Выполните обновлённый `supabase/schema.sql` (шаг 5): он переименует старые цвета. Санта может выбрать новый цвет в карточке |
| Нажимаю Re-run, а ошибка повторяется | Re-run повторяет старую попытку с тем же кодом | Если вы уже закоммитили исправление — не жмите Re-run: после **Push origin** новая сборка запускается сама. Или нажмите **Run workflow**. Re-run помогает, только когда менялись секреты/настройки, а не код |
| Сборка падает на шаге Check secrets | Нет одного или обоих секретов | Выполните шаг 14, затем **Re-run jobs** |
| Сборка на вкладке Actions завершилась красным крестиком | Другая ошибка сборки | Откройте упавшую сборку, прочитайте лог упавшего шага. Чаще всего помогает: проверить шаг 13 (все файлы на месте) и шаг 14 (секреты), затем **Re-run jobs** |
| Сайт открывается, но вместо ёлки жёлтое предупреждение «сайт не подключён к Supabase» | Секреты не попали в сборку | Проверьте шаг 14 (точные имена, значения без пробелов) и перезапустите сборку (**Re-run jobs**). Ключи вшиваются в сайт только во время сборки |
| При регистрации ошибка про подтверждение почты | Включён Confirm email в Supabase | Выполните шаг 6: выключите **Confirm email** и сохраните. Перезапускать сборку не нужно |
| «Этот адрес уже зарегистрирован» | Почта уже зарегистрирована, в том числе с другим регистром букв | Войдите или нажмите **Забыли пароль?** |
| «Неверная почта или пароль» | Опечатка либо такого профиля нет | Проверьте адрес и раскладку. Если забыли пароль — восстановите его ссылкой из письма |
| Письмо для смены пароля не приходит | Не задан Site URL, письмо в спаме | Проверьте папку «Спам». Убедитесь, что в Supabase (**Authentication → URL Configuration**) поле **Site URL** равно адресу сайта. Перезапускать сборку не нужно |
| «Ссылка недействительна или устарела» | Ссылка открыта в другом браузере или слишком старая | Запросите новую ссылку кнопкой **Забыли пароль?** и открывайте её в том же браузере |
| Ошибка вида «new row violates row-level security» или «permission denied» | В базе старый `schema.sql` без функций | Повторите шаг 5 с актуальным файлом `supabase/schema.sql` из репозитория |
| «Ошибка сервера» / ошибки при входе после недели простоя | Бесплатный проект Supabase «уснул» | «Разбудите» его (раздел «После запуска») |
| Сайт долго не обновляется после Push | Сборка ещё идёт или браузер показывает старую версию | Дождитесь зелёной галочки на вкладке **Actions**, затем обновите страницу через **Ctrl+F5** |
| В GitHub Desktop виден файл `.env` | Файла `.gitignore` нет в папке проекта | Не делайте commit. Убедитесь, что `.gitignore` скопировался (он скрытый — см. подсказки в шаге 9) |

# Безопасность

- Публичный ключ Supabase (`NEXT_PUBLIC_SUPABASE_ANON_KEY`) **не секретный** — он виден в собранном сайте, и это нормально. Прямой доступ к таблицам закрыт, а функции базы отдают каждому только его данные и проверяют все права.
- Секретный ключ проекта Supabase сайту не нужен. Никуда его не вписывайте и никому не показывайте.
- Файл `.env` храните только на своём компьютере. На GitHub его загружать нельзя.
- Пароли пользователей хранит Supabase в зашифрованном виде. Сайт и его владелец их не видят.
